# ⚠️ NO LONGER WIRED BY THE SHIPPED CONFIGS (T-576, kit > 1.9.4).
#   The `presidio.strict_safe_terms_file:` directive that used to point here was
#   RETIRED by the sanitizer (services/sanitizer/config.py, commit 811ef43b0
#   2026-07-25) and is now a BOOT REFUSAL, not a no-op — leaving it set
#   CrashLoopBackOffs the sanitizer and the whole stack fails to come up.
#   The ten terms below now live inline in config/default-sanitizer.yaml under
#   `sanitizer.redaction_policy.stop_terms` with `surface: l1_strict`, which is
#   where the current sanitizer reads them from. EDIT THEM THERE — editing this
#   file changes nothing on a shipped config.
#
#   This file and its Compose bind-mount are retained only so an operator still
#   pinned to a PRE-2026-07-25 sanitizer image, running their own config that
#   still sets the old directive, keeps a real host-side source for the mount
#   (a missing bind-mount source would materialize as an empty directory).
#   Everything below documents the semantics, which the l1_strict surface
#   reproduces byte-for-byte.
#
# SEMANTICS (different from config/medical-terms.txt):
#   A Presidio/spaCy NER detection is suppressed ONLY when the ENTIRE detected
#   span (lowercased + stripped) exactly equals a term here. No first-word
#   match, no any-word match. This prevents under-redaction of real names whose
#   first token happens to be a safe term:
#
#     "claude"         alone → suppressed  (product vocabulary FP)
#     "claude müller"  → NOT suppressed    (real person's full name; span
#                                           differs from "claude")
#
# DO NOT add real given names here. "marc" is a real given name tagged
# PERSON@0.85 by spaCy — safe-listing it would be an under-redaction that
# leaks real identity data. (See Slice 1 findings and the "claude müller"
# adversarial test in test_overredaction_recall_fixture.py.)
#
# "grep" was considered (it is tagged PERSON@0.85 in the conv-3cde524c run)
# but intentionally dropped: it is also a real-world surname. Errs toward
# over-redaction by design.
#
# Source: Slice 2 of PRD prd-2026-06-14-overredaction-tuning.md.
